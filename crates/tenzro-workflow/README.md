# Tenzro Workflow

Multi-party workflow primitive for Tenzro Network — typed obligations, policy-gated approvals, hash-chained receipts, privacy domains, fee routing, and a kill switch. Workflows are Tenzro-native first and replicate to Canton via the co-located participant Ledger API.

## Scope

A `Workflow` is a typed container that owns:

- `Participant`s with `ParticipantRole`s,
- `Obligation`s tied to typed `DischargeProofKind`s,
- `ApprovalGate`s wired to a composite `PolicyExpr` and `ApproverSet`,
- a `WorkflowStatus` lifecycle with full `LifecycleTransition` history (`Draft → Active → AwaitingSignatures → Executing → Completed` plus terminal `Cancelled / Disputed / Failed / Suspended`),
- optional `CantonMirror` pointer for replication to a Canton synchronizer,
- optional `PrivacyDomainId` and `FeeRouteId` references.

## Module map

| Module | Purpose |
|---|---|
| `workflow` | `Workflow`, `WorkflowStatus`, `CantonMirror`, `ParticipantSignature` |
| `participant` | `Participant`, `ParticipantRole` |
| `obligation` | `Obligation`, `ObligationStatus`, `ObligationKind`, `DischargeProof` |
| `approval` | `ApprovalGate`, `ApprovalRequest`, `ApprovalDecision`, `ApproverSet` |
| `policy_dsl` | Composite `PolicyExpr`, pure `evaluate(expr, ctx)` — combinators: `amount_lte`, `daily_amount_lte`, `counterparty_kyc_tier_gte`, `time_window`, `and`, `or`, `not` returning `PolicyOutcome::{Allow, Deny, RequireApproval}` |
| `lifecycle` | `LifecycleTransition`, `TransitionTrigger`, `KillSwitchScope` |
| `receipt` | `WorkflowReceipt` projecting to `tenzro_storage::da::ReceiptEnvelope` (per-kind `Inline` vs `OffloadedDA` defaults) |
| `privacy` | `PrivacyDomain` ACL with auditors subset, AES-256-GCM `seal` / `open`, governance-driven freeze |
| `fee_route` | `FeeRoute` + `FeeSplit` basis-point splits (sum=10000), truncation + remainder-to-last |
| `metrics` | `OperationalMetrics` snapshot rendered to Prometheus text format with `BTreeMap` ordering |
| `codegen` | `WorkflowDamlCodegen` generates the Canton/Daml projection from a workflow + map |
| `manager` | `WorkflowManager` with `DashMap` indices and `write_batch_sync` persistence to `CF_SETTLEMENTS` / `CF_APPROVALS` |

## Receipts

Every workflow event emits a `WorkflowReceipt` linked to the previous receipt by hash (anchored at `Hash::default()`). Receipts project to `ReceiptEnvelope` with per-kind defaults — most workflow events are `Inline`; high-volume kinds may be `OffloadedDA` to a configured backend (`InlineFallbackBackend` is the safe default until EigenDA / Celestia / Avail adapters land behind feature flags).

## Canton receipt mirror

`tenzro-workflow` emits a `Tenzro.Workflow.Receipt` Daml contract through the co-located participant Ledger API for every receipt that opts in via `CantonMirror`. The Daml template is generated by `WorkflowDamlCodegen` from a `*_daml_map.json` paired with each workflow spec.

## `WorkflowRuntime`

The node bundles `WorkflowManager`, `PrivacyDomainRegistry`, and `FeeRouteRegistry` as a single `WorkflowRuntime`, wired into startup alongside the AI infrastructure. RPC, MCP, and A2A surfaces are exposed through `tenzro-node`:

- **RPC:** `tenzro_getWorkflow`, `tenzro_getWorkflowLifecycle`, `tenzro_listWorkflowsByCreator`, `tenzro_listWorkflowsByParticipant`, `tenzro_listWorkflowsByStatus`, `tenzro_getWorkflowReceipt`, `tenzro_listWorkflowReceipts`, `tenzro_getFeeRoute`, `tenzro_listFeeRoutes`, `tenzro_computeFeeRoutePayouts`, `tenzro_getPrivacyDomain`, `tenzro_listPrivacyDomainsForDid`, `tenzro_getWorkflowOperationalMetrics`.
- **MCP:** matching tools registered on the main MCP server (port 3001).
- **A2A:** `workflow` skill in the Tenzro agent card.

## Reference workflows

Five reference workflows under `reference_workflows/`, each paired with a `*_daml_map.json` describing the Canton projection:

| Workflow | Purpose |
|---|---|
| `autonomous_procurement` | Buyer/seller/auditor procurement on Canton with DvP |
| `autonomous_treasury` | Multi-sig treasury operations with policy-gated approvals |
| `dvp_settlement` | Delivery-vs-payment settlement on a Canton synchronizer |
| `environmental_mrv` | Environmental measurement / reporting / verification with auditor sign-off |
| `supply_chain_dpp` | Supply-chain digital product passport with multi-party attestations |

> **Distinct from agent templates.** `crates/tenzro-agent-kit/reference_templates/` describes single-agent execution pipelines and is a separate concept.
