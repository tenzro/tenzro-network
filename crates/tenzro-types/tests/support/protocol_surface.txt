# The node's and VM's protocol surface, one entry per line:
#   <kind> <name> <class> <decision-log id>
# boundary_guard fails when the source has a native module, native selector,
# RPC namespace or RPC method that is not listed here, so every addition to the
# surface is a reviewed change to this file. The id names an entry in
# docs/LAYERS.md; a line with no entry fails the guard.
#
# Classes:
#   P  protocol: consensus, identity, accounts and tokens, staking and roles,
#      settlement and escrow, metered receipts, the service registry, disputes
#      and slashing, governance and governed parameters, bridges
#   R  node role service: work a bonded node performs and is paid for through
#      the rails (model serving of every modality, storage, TEE attestation)
#   N  node infrastructure: p2p networking, mempool and admission, sync and
#      block storage, RPC and MCP serving, metrics
#
# The U (under review) class is gone: the guard rejects it. A few H lines
# (application layer, three columns, no id) remain only until their removal
# commit; the guard caps their number and they may only be removed.
# A new entry must be P, R or N with a decision-log id.
