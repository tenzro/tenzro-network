# AP2 v0.2 Research — Agent Payments Protocol

**Date:** 2026-05-05
**Source:** https://ap2-protocol.org/ap2/specification/

## Mandate types

- **Checkout Mandate** — `vct: "mandate.checkout.1"` or `"mandate.checkout.open.1"` (autonomous)
- **Payment Mandate** — `vct: "mandate.payment.1"` or `"mandate.payment.open.1"` (autonomous)
- **Intent Mandate** — pre-authorized autonomous flows

Required claims: `vct`, `checkout_hash` (binds Payment Mandate to Checkout JWT via SHA-256), `cnf` (agent's public key JWK, required for `open` mandates), `exp`, `transaction_id`.

## Cryptographic requirements (verbatim)

> "the Checkout JWT MUST be signed using a digital signature scheme (e.g., ECDSA) and not a deterministic signature (e.g., Ed25519)"

Format: **SD-JWT VC** (compact serialization with `~`-separated disclosures). Curve unbound, ES256 (P-256) is de facto. Non-determinism is mandated to prevent fault-injection key recovery.

## 5 roles (separation-of-duties)

1. Shopping Agent — discovery, cart assembly, purchase execution
2. Credential Provider — payment credential issuance + auth
3. Merchant — checkout integrity, inventory/pricing
4. Merchant Payment Processor (MPP) — settlement, scope verification
5. **Trusted Surface — explicit user consent capture; MUST be non-agentic**

> "A role is Agentic when communication to or from the Role is handled by a non-deterministic LLM"

## Anchoring

**The core spec is purely off-chain JWT exchange — zero mentions of DIDs, blockchain, or on-chain anchoring.** A2A x402 extension routes settlement through USDC `transferWithAuthorization`, but the mandate itself remains an off-chain SD-JWT-VC. **No implementer (Salesforce, Shopify, PayPal, Mastercard) anchors mandates to DIDs or chain state as of 2025-10.**

## Tenzro angle (YES)

1. **TDIP DID anchoring of `cnf`**: `cnf` claim carries `did:tenzro:machine:*` whose DID Document holds the JWK. Verification = DID resolution + `IdentityRegistry::enforce_operation()` + runtime `SpendingPolicy` check.
2. **On-chain escrow settlement**: Payment Mandate `transaction_id` binds to Tenzro `CreateEscrow` (selector `0x01000010`); settlement proof = block inclusion + receipt. Stronger dispute primitives than EIP-3009 transfer (payer-only refund, expiry).
3. **AgentBond enforcement**: `tenzro bond post` collateral slashable on mandate violations. Nobody else has this primitive.

## Implementation order

1. **Spec conformance** (in progress): `MandateKind::Checkout`/`Payment` and `MandatePayload::Checkout`/`Payment` in `crates/tenzro-payments/src/ap2/mod.rs` — DONE. `vct` claim accessor — DONE. `checkout_hash` SHA-256 binding — DONE. Remaining: replace Ed25519 `Vdc` envelope with SD-JWT VC compact serialization (`header.payload.signature~disclosure1~...`), add ECDSA P-256 signing path alongside Ed25519 (spec mandates non-deterministic).
2. **TDIP DID anchoring** (DONE): `cnf` accepts JWK or DID via `MandateCnf::{Jwk, Did}`. `Vdc::verify_with_registry(&IdentityRegistry)` enforces both forms — JWK `x` must equal `signer_public_key`; DID must equal `signer_did`, must resolve, and signer key must appear in resolved DID Document. Wired into `MandateValidator::validate_with_delegation_and_policy()` before structural checks. 6 unit tests cover happy-path + 4 confusion-attack rejections. Surfaced in `tenzro_protocolInfo` AP2 `cnf_enforcement` block.
3. **Escrow binding** (DONE): `MandateValidator::validate_with_delegation_policy_and_escrow()` consults a pluggable `EscrowResolver` (`crates/tenzro-payments/src/identity_binding.rs`) when the mandate pair carries `escrow_id`, projecting on-chain `EscrowAccount` state into an `EscrowSnapshot` and rejecting unless the escrow exists, is `Funded` and not expired, and locks at least `payment.total_amount`. Node-side `EscrowManagerResolver` (`crates/tenzro-node/src/escrow_resolver_bridge.rs`) bridges `EscrowManager`. 7 unit tests cover happy-path + 5 rejection paths. Surfaced as the **fourth ceiling** in `tenzro_protocolInfo` AP2 `ceilings` array.
4. **AgentBond binding** (DONE): `tenzro_ap2ReportMandateViolation` is the AP2-flavored claim-filing entry point. It verifies the parent CheckoutMandate VDC, optionally cross-verifies a child PaymentMandate (signature + parent-binding + agent-DID match), validates the violation classification (`overspend` / `merchant_whitelist_breach` / `category_breach` / `expired_mandate_settlement` / `double_spend` / `missing_cnf_binding` / `other`), confirms the agent has a posted AgentBond, and forwards to `BondManager::file_claim()` with a structured narrative capturing kind + mandate IDs + caps + asset. Slash dispatch follows the standard AgentBond flow: open claim → governance review → `approve_claim` → `PayInsuranceClaim` typed transaction → on-chain `BondSlashed` log reflected back into `BondManager`. Surfaced as `agent_bond_enforcement` in `tenzro_protocolInfo` AP2 block.
