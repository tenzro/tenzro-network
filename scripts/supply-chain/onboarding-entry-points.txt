# R35: every way in, and why none of them lets a participant act without a hardware-rooted wallet
# and identity (TPM, delegated TPM, Secure Enclave, passkey). check-onboarding.sh fails on an entry
# that is not listed here. Line format: <kind> <name> <reason>. A reason is a sentence, not a word.
#
# The start gate is crates/tenzro-node/src/main.rs run(): after the config and role checks and the
# optional --tpm-key-holder, `require_hardware_key_store`, the TPM provisioning check and
# `require_hardware_identity` run before node_config, storage, networking, RPC or any role. There is
# no keyless mode. crates/tenzro-node/tests/onboarding_guard.rs starts the binary with each
# bypass-shaped combination and asserts it is refused on a machine with no hardware key.
#
# Adding a line here is a review decision: say what the entry does before the gate (it should do
# nothing) and what stops it after.

# --- tenzro-node subcommands ---
node-sub access administers who may use a node; the node checks the caller
node-sub backup copies the local store; starts or registers nothing
node-sub clear credentials clear; removes a credential
node-sub credentials stores upstream credentials in the data directory
node-sub doctor reachability report; read-only except --allow-inbound, a host firewall rule
node-sub graceful-exit RPC client of a running node (a node past the start gate)
node-sub grant-install installs a grant only with the operator passkey's assertion
node-sub grant-request prints the challenge an operator passkey must sign; nothing is granted
node-sub hardware reports what this binary can use on this machine; read-only
node-sub init prints this machine's validator entry from its hardware keys (from_local_hardware); refuses on a machine with none
node-sub key-holder carries a delegated node's signing requests to the provider; signs nothing itself
node-sub prover-inputs prints inputs for a prover run; read-only
node-sub provision creates the three persistent TPM keys; the hardware root itself
node-sub remote-check asks the provider to sign through the key holder; read-only proof
node-sub restore verifies and restores a store snapshot; starts or registers nothing
node-sub serve a provider serving its own TPM to delegated nodes; needs that TPM
node-sub set credentials set; stores a credential
node-sub status credentials status or tpm status; read-only
node-sub tpm TPM subcommands; each listed on its own
node-sub validator-entry prints this machine's genesis entry from its hardware keys; refuses on a machine with none
